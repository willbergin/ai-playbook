# Builder

The Builder owns the implementation and the checks that can be repeated. Start with the scoped issue, acceptance criteria and app instructions.

## What to do

Follow [implement-issue](../skills/implement-issue/SKILL.md). Preserve work already in the repository and tell the Lead if the required change falls outside the agreed scope. Use the app’s test commands and nonproduction targets.

Update affected docs with [document](../skills/document/SKILL.md). When a model or prompt changes, include the [evaluation results](../skills/evaluate-ai-change/SKILL.md) in the candidate’s evidence.

## What to hand over

Use the [handoff template](../prompts/handoff.md) to give Reviewer the change request, exact candidate commit, commands and results, preview status and checks that still need to run.

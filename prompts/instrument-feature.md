# Instrument a feature

> Use the issue and acceptance criteria to draft a measurement brief. State the product question, the decision it will inform, and the existing analytics tool that can answer it. List any event names, exact triggers, allowed properties, and how to check that events fire once in a test journey. Identify application failures worth reporting in Sentry, with release and environment tags and the minimum diagnostic context. Omit secrets and sensitive payloads. Explain how to verify event and error delivery in nonproduction. Flag any decision that needs input.

The Lead can attach the brief to the issue. The Builder can implement approved instrumentation, and the Reviewer can check its evidence.
